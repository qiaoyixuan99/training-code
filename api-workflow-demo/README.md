# 搭建工作流调用 API — 实战演示

> 把多个独立的 API 按业务逻辑编排成一条自动管道，
> 让数据和任务自动流转，无需人工干预。

## 运行方式

```bash
cd api-workflow-demo
python -X utf8 workflow_demo.py
```

## 三种核心模式

### 1. 🔗 链式调用 (Chain)
```
名言API → 翻译API → 推送消息
           ↑输出成为输入
```

**真实场景:** 每天自动收集科技新闻 → AI 总结 → 发到飞书群

### 2. 🔀 条件分支 (Branch)
```
             ┌→ 在线 → 查询天气 → 决定行动
检查网络状态 ─┤
             └→ 离线 → 使用缓存数据
```

**真实场景:** 下单接口超时 → 重试 3 次 → 仍失败则发告警邮件

### 3. ⚡ 并行 + 汇总 (Fan-out/Fan-in)
```
     ┌→ IP查询  ─┐
同时 ─┼→ 时间服务 ─┼→ 汇总报告
     └→ 用户代理 ─┘
```

**真实场景:** 同时查多个数据库 → 生成一份综合报表

## 真实项目结构

```
每日 AI 新闻工作流:
  HackerNews API → OpenAI 总结 → 飞书 Webhook
       ↑                ↑              ↑
     数据源           AI 处理         推送通知
```

## 实现方式对比

| 方式 | 门槛 | 适合场景 |
|------|------|----------|
| **Python + APScheduler** | 中 | 开发者，需要灵活控制 |
| **n8n 可视化拖拽** | 低 | 非开发者，快速搭建 |
| **GitHub Actions** | 低 | 免费，定时任务 |
| **Dify / Coze** | 低 | AI 工作流，中文友好 |
| **LangGraph** | 高 | 复杂多步骤 Agent |
| **Apache Airflow** | 高 | 企业级数据管道 |

## 一句话总结

> **"搭建工作流调用 API" = 像搭积木一样把多个 API 串起来，让它们自动协作完成一个完整任务。**
